② 策略模式（Strategy）精讲 出题频率第一

意图（背）：定义一系列算法，把它们一个个封装起来，并且使它们可以互相替换。客户端在运行时切换算法，算法变化不影响使用算法的客户。
// 仿真真题：支付方式可切换
interface PaymentStrategy {              // 抽象策略（挖空常考接口名）
    void pay(int amount);
}
class AliPay implements PaymentStrategy { // 具体策略 A
    public void pay(int amount) { System.out.println("支付宝支付" + amount); }
}
class WechatPay implements PaymentStrategy { // 具体策略 B
    public void pay(int amount) { System.out.println("微信支付" + amount); }
}
class CashContext {                       // 环境类：持有一个策略引用
    private PaymentStrategy strategy;     // ★高频挖空：成员类型 = 抽象策略（多态！）
    public void setStrategy(PaymentStrategy strategy) {  // 参数类型同样是抽象策略
        this.strategy = strategy;          // ★高频挖空：this.
    }
    public void checkout(int amount) {
        strategy.pay(amount);              // ★高频挖空：调用的变量名（多态分派）
    }
}
// 使用：ctx.setStrategy(new AliPay()); ctx.checkout(100);
策略模式填空三板斧：① 环境类的成员变量类型 = 抽象策略接口；② set/构造方法参数 = 同一个接口；③ 调用处 = strategy.pay(...) 这个变量名而不是具体类名。认准这三处，15 分稳一半。

③ 高频设计模式速查表（近十年真题覆盖）必须全认识

模式一句话意图（题目问"该模式是？"就按这个选）代码/类图识别标志
策略 Strategy封装一系列可互相替换的算法接口 + 多个实现类 + 环境类持有接口引用
观察者 Observer对象状态变化时自动通知所有依赖者attach/detach/notify + 子类列表 + update()
装饰器 Decorator动态地给对象添加职责，比继承灵活装饰类继承并持有同一抽象类型的引用
工厂方法 Factory Method定义创建对象的接口，让子类决定实例化哪个类abstract Creator + factoryMethod() 返回产品
抽象工厂 Abstract Factory创建一系列相关产品对象（产品族）抽象工厂接口有多个创建方法
单例 Singleton保证一个类仅有一个实例并提供全局访问点private 构造函数 + static getInstance()
适配器 Adapter把一个类的接口转换成客户期望的另一个接口适配类继承目标接口 + 持有被适配者
外观 Facade为子系统的一组接口提供统一的高层入口一个类的方法里依次调用多个子系统方法
代理 Proxy为其他对象提供占位/控制访问代理类与真实类实现同一接口，代理里 new 真实类
模板方法 Template Method父类定义算法骨架，子类实现某些步骤抽象父类 final 方法按顺序调用抽象方法
状态 State对象行为随内部状态改变而改变环境类持有状态引用，状态子类可切换状态
桥接 Bridge把抽象部分与实现部分分离，独立变化抽象类持有"实现"接口的引用
易混三组（选择题陷阱）：① 代理 vs 装饰器：代理控制访问（远程/权限），装饰器加职责；② 外观 vs 适配器：外观是"简化打包一堆子系统"，适配器是"接口转换"；③ 工厂方法 vs 抽象工厂：一个产品用工厂方法，一族产品用抽象工厂。

④ 装饰器（Decorator）精讲 第二高频

// 仿真真题：给咖啡动态加配料
interface Coffee { double cost(); String desc(); }  // 抽象构件
class SimpleCoffee implements Coffee {               // 具体构件
    public double cost() { return 10.0; }
    public String desc() { return "咖啡"; }
}
abstract class CoffeeDecorator implements Coffee {   // 装饰器：实现同一接口
    protected Coffee coffee;                          // ★核心挖空：持有同一类型引用
    public CoffeeDecorator(Coffee coffee) { this.coffee = coffee; }
}
class Milk extends CoffeeDecorator {                 // 具体装饰器：继承装饰器
    public Milk(Coffee coffee) { super(coffee); }    // ★挖空：super(coffee)
    public double cost() { return coffee.cost() + 2.0; }  // ★委托 + 加价
    public String desc() { return coffee.desc() + "+牛奶"; }
}
// 使用：Coffee c = new Milk(new SimpleCoffee()); → 12.0，"咖啡+牛奶"
装饰器识别三标志：① 装饰类 extends/implements 同一个抽象；② 成员变量类型 = 被装饰的抽象类型；③ 方法体 = coffee.cost() 再加点什么（委托+增强）。三者齐 = 装饰器，没有例外。

⑤ 高频模式代码骨架（观察者 / 单例 / 工厂方法）背骨架

这三个模式的填空题频率仅次于策略和装饰器。骨架很短，记"挖空点"就行：

▶ 观察者 Observer（识别词：attach / notify / update）

interface Observer { void update(float temp); }
class WeatherData {                                // 被观察者（主题）
    private List<Observer> obs = new ArrayList<>();
    public void attach(Observer o) { obs.add(o); }        // ★挖空：注册
    public void dataChanged() {
        for (Observer o : obs) o.update(temp);           // ★挖空：遍历通知
    }
}
class PhoneDisplay implements Observer {           // 观察者
    public void update(float temp) { /* 刷新显示 */ }
}
观察者填空点：① 主题里放的是 List<Observer>（抽象类型列表）；② attach 里 add；③ 通知处遍历调用 o.update(...)。

▶ 单例 Singleton（识别词：private 构造 + static getInstance）

class Config {
    private static Config instance;              // ★唯一实例（static）
    private Config() {}                          // ★私有构造：禁止外部 new
    public static Config getInstance() {         // ★全局访问点
        if (instance == null) instance = new Config();
        return instance;
    }
}
单例三件套：private 构造 + private static 实例 + public static getInstance()——三处都可能挖空，尤其 private Config() 和 getInstance。

▶ 工厂方法 Factory Method（识别词：抽象工厂 + createXxx() 返回抽象产品）

abstract class Logger { public abstract void write(String msg); }   // 抽象产品
class FileLogger extends Logger { public void write(String m){} }  // 具体产品
abstract class LoggerFactory {
    public abstract Logger createLogger();       // ★工厂方法：返回抽象类型
}
class FileLoggerFactory extends LoggerFactory {
    public Logger createLogger() { return new FileLogger(); }  // ★决定造哪个
}
// 使用：LoggerFactory f = new FileLoggerFactory(); f.createLogger().write("hi");
工厂方法填空点：① 工厂方法返回类型 = 抽象产品；② 具体工厂里 new 具体产品；③ 使用方拿抽象类型接住（多态）。和策略的区别：工厂管"创建"，策略管"行为切换"。
