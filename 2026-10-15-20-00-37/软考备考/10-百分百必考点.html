上午 · 铁打必考（14 张，近 10 年年年出）

★必开发模型选型1~2 分

考

题干描述一个项目的特点，问"最适合采用哪种开发模型"。

懂

各种模型的本质区别是"怎么应对需求变化和风险"：瀑布假设需求从不变一路到底；原型先做个样品让用户看清楚自己要什么再正式开发；增量把系统切成几块，每次交付一块能用的；螺旋每一圈都先做风险分析，风险大就调整方向；敏捷小步快跑拥抱变化。

算

看到"风险分析/风险驱动"→螺旋；"需求不明确，先开发一个样给用户确认"→原型；"分批交付、核心功能先上线"→增量；"文档驱动、评审通过才进下一阶段"→瀑布；"每日站会、结对编程"→敏捷。

坑

增量 vs 原型：增量交付的是"真正能用的功能分批上线"，原型交付的是"用来确认需求的样品（看完可能扔掉）"。

★必白盒覆盖 + McCabe1~2 分

考

①给几种覆盖问强弱排序；②给程序图数边和节点求 V(G)。

懂

白盒测试是"把代码里所有可能的执行路线尽量走一遍"。覆盖越强=走的路线越全=找 bug 越彻底，但设计用例成本也越高。语句覆盖只要求每行代码被执行一次（最弱）；路径覆盖要求每条完整路线都走（最强）。V(G) 的含义是"程序里独立路线的条数"，也就是覆盖全部独立路线所需的最少用例数。

算

排序：语句＜判定＜条件＜判定/条件＜条件组合＜路径。V(G) = 边 − 节点 + 2：程序图 10 条边 8 个节点 → 10−8+2 = 4 → 至少 4 个用例。另一公式：判定（if/while）节点数+1。

坑

排序别背反（最强是路径、最弱是语句）；公式方向是"边−点"，不是"点−边"。

★必耦合内聚排序1~2 分

考

描述两个模块怎么交互，问属于什么耦合/内聚；或直接问"耦合最差/内聚最好的是"。

懂

耦合=模块之间联系的紧密程度（越松越好——改一个模块不影响另一个）；内聚=模块内部各元素配合的紧密程度（越紧越好——一个模块只干一件相关的事）。好的设计就是八个字"高内聚、低耦合"。

算

耦合从好到差"数标控外公内"：只传一个数值=数据；传结构/记录=标记；传开关命令操纵别人=控制；共享软件环境=外部；共享全局数据=公共；直接读写别人内部数据=内容。内聚从好到差"功顺通过时逻偶"：一件事干到底=功能；上一步输出是下一步输入=顺序；围绕同一数据集=通信；按固定流程=过程；同一时段凑一起=时间；靠参数挑着执行=逻辑；毫无关系=偶然。

坑

逻辑内聚：一个模块干好几件事、靠传入的参数决定执行哪个——考题爱拿它和功能内聚混淆。

★必设计模式固定 2~3 分

考

给一段业务场景描述选模式（下午还考代码填空）。

懂

设计模式是前人总结的"代码套路"，考试核心是"从场景描述识别套路"。策略=把几种算法各自封装成类，运行时随便换；观察者=一个对象状态变了，自动通知所有关注它的对象；装饰器=不改原类、像穿衣服一样层层叠加新功能；单例=全局只允许一个实例；工厂方法=把"new 哪个类"推迟给子类决定；状态=对象的行为随内部状态自动切换。

算

"系统只有一份/全局访问点"→单例；"状态变化通知所有依赖者"→观察者；"动态加职责、不增加子类"→装饰器；"算法可替换"→策略；"行为随状态改变"→状态；"由子类决定创建哪个"→工厂方法。

坑

状态 vs 策略结构几乎一样（都是接口+一组实现类），区别在"谁来换"：外部换算法=策略，对象自己随状态切换=状态。

★必流水线1~2 分

考

给各段耗时和指令条数，求总时间/加速比/吞吐率。

懂

流水线像工厂装配线：第一条指令要完整走完所有段（所以第一条=各段之和）；之后每过一个"周期"就有一条指令完工——因为各段同时都在干活，节奏由最慢的那段决定（木桶效应）。

算

总时间 = 各段之和 + (n−1)×周期。例：四段 1/2/3/4ns 跑 100 条 → 第一条 10ns，之后 99 条每 4ns 出一条 → 10+99×4 = 406ns；加速比 = 不流水时间÷流水时间 = 100×10 ÷ 406 ≈ 2.46；吞吐率 = 100÷406ns。

坑

周期 = 最长的那段（短板）；加速比不是"段数"倍。

★必Cache 平均访问时间1 分

考

给命中率、Cache 时间、主存时间，求平均访问时间。

懂

CPU 要数据先问 Cache（快而小），命中就直接拿（用 t1）；没命中（概率 1−H）只能去慢的主存拿（用 t2）。平均时间就是两种情况的加权平均。"同时访问"式是指 Cache 和主存同时开始查，命中就丢掉主存的结果——所以未命中时主存那段时间里其实还搭进去了一次 Cache 时间。

算

顺序式：T = H×t1 + (1−H)×t2 = 0.9×40 + 0.1×200 = 56ns。同时访问式：T = 0.9×40 + 0.1×(40+200) = 60ns。

坑

题干有没有"同时访问"四个字决定用哪个公式，差 4ns 就是两个选项。

★必可靠性1 分

考

给串并联结构图和各部件可靠度，求系统整体可靠度。

懂

串联=一个坏全坏（所有部件都必须活着系统才活着，所以可靠度相乘，越串越低）；并联=坏一个还有备份（只要不是全坏系统就活着，用"全坏的概率"算：1−∏(1−R)，越并越高）。

算

混联口诀"先小后大"：先把每个并联小组算成一个数，再串联。例：两个子系统串联，各由 2 个 0.9 并联 → 每组 = 1−0.1² = 0.99 → 系统 = 0.99×0.99 = 0.9801。

坑

并联结果一定比组内任何一个部件都高；别把混联一笔相乘。

★必页式地址转换1~2 分

考

给页大小、逻辑地址、页帧映射表，求物理地址。

懂

分页把内存切成一样大的小方块。逻辑地址由"页号 + 页内偏移"拼成：页号说明在哪个页，偏移说明在页内第几个字节。页大小都是 2 的幂（1KB=2¹⁰），所以地址的低 k 位天然就是偏移，高位就是页号。页在内存里被放到哪个帧由映射表决定；同一页搬到哪里，页内偏移都不变。

算

三步：①偏移位数 = log₂(页大小)，1KB→10 位；②页号 = 逻辑地址 ÷ 页大小（取商），偏移 = 余数。例：2500÷1024 → 页号 2、偏移 452；③物理地址 = 帧号×页大小+偏移 = 4×1024+452 = 4548。

坑

帧号必须查题干给的映射表，别拿页号直接当帧号；4KB 页就用 4096 除。

★必排序1~2 分

考

①问稳定性/复杂度；②给序列问"第一趟之后"的样子。

懂

"一趟"的含义每种排序不同：插入=把下一个元素插进前面已排好的部分（一趟后只有前 2 个有序）；冒泡=从头两两比较，把最大数顶到末尾（一趟后 1 个就位）；选择=全表找最小换到首位（一趟后 1 个就位）；快排=枢轴归位（一趟后枢轴一定在最终位置）。稳定性=相等的元素排完序后先后次序是否保持。

算

45,23,12,9：插入→23,45,12,9；冒泡→23,12,9,45；选择→9,23,12,45；快排（枢轴45）→45 落最终位。不稳定口诀"快些选堆"（快排/希尔/选择/堆）。

坑

希尔的一趟是"按增量分组各排"，与其他完全不同，别套上面的判断。

★必二叉树1~2 分

考

①给叶子数求度 2 节点数；②给前序+中序求后序。

懂

n0=n2+1 的来历：二叉树所有边的条数 = 节点数−1 = n1+2n2，又是 n0+n1+n2−1，两边消掉 n1 得 n0=n2+1。遍历重建的原理：前序第一个一定是根；在中序里，根左边全部属于左子树、右边全部属于右子树——拿根把中序切成两半，再递归处理。

算

5 个叶子 → n2 = 4。重建：前序 ABDECF + 中序 DBEAFC → 根 A，左半 DBE、右半 FC → 左子树根 B（D、E 是它的左右孩子）→ 右子树根 C（F 是左孩子）→ 后序（左右根）= DEBFCA。

坑

前序+后序不能唯一重建（分不出左右）；哈夫曼树 n 叶子共 2n−1 个节点、没有度 1 节点。

★必子网划分1 分

考

给 IP 和掩码（或 /n 写法），求可用主机数或子网数。

懂

掩码里二进制 1 的部分是"网络号"（小区名），0 的部分是"主机号"（门牌号），/n 写法就是"1 有 n 个"。主机位有 h 位就有 2^h 个地址，但全 0 代表"网络本身"、全 1 是"广播地址"，都不能分给主机——所以要减 2。

算

/27 → 主机位 = 32−27 = 5 → 可用 = 2⁵−2 = 30 台；比 /24 多借 3 位 → 子网数 = 2³ = 8 个。

坑

必须减 2；/26→62、/28→14 是高频数字；127.0.0.1 是本机回环。

★必TCP/UDP + 协议端口1~2 分

考

给特征选协议、给应用选端口。

懂

TCP 像打电话：先拨号确认接通（三次握手），说话有确认重发——可靠但慢；UDP 像广播喊话：不确认、丢了就丢——快但不可靠。端口是同一台电脑上不同服务的"门牌号"，常用端口是硬背的。

算

可靠+面向连接→TCP（网页、邮件、文件传输）；实时要快→UDP（视频、语音、DNS 查询）。端口：FTP 20/21、SMTP 25、DNS 53、HTTP 80、HTTPS 443。

坑

"视频会议/直播"选 UDP（要快不要重发）；DHCP 是自动分配 IP，不是域名解析。

★必PV 操作1~2 分

考

给伪代码挖空填 P/V，或问信号量初值。

懂

P=申请资源（没有就等着），V=释放资源（叫醒等待的人）。互斥用一把锁（初值 1）；同步用"资源计数"（empty=还能放几个、full=已有几个）。两个 P 的顺序错会死锁：生产者先拿锁再等空位，缓冲区满时它抱着锁睡觉，消费者想取货却进不了锁——互相等死，这就是"同步在前、互斥在后"的原因。

算

生产者：P(empty)→P(mutex)→放→V(mutex)→V(full)；消费者对称。初值：empty=n（缓冲区大小）、full=0、mutex=1。

坑

mutex 的 P/V 必须成对夹住操作；选项里出现"P(mutex) 在 P(empty) 之前"直接判错。

★必知识产权2~3 分

考

情境题：问著作权归谁、是否侵权、保护期多久。

懂

三类权利的取得方式不同：著作权=作品完成那一刻自动拥有（登记只是举证方便）；专利=必须向国家申请、审查通过才授予（所以有审查期）；商标=注册才有效、10 年一续可无限续展。委托开发在没约定时归"实际干活的一方"（受托方）。

算

职务开发→归公司；委托无约定→受托方；自然人著作权 = 终生 + 死后 50 年（当年 12.31 止）；法人软件 = 首次发表后 50 年；专利：发明 20、实用新型 10、外观设计 15（自申请日起）。

坑

"有登记证书"≠登记才取得著作权；专利期限自申请日起算，不是授权日。

上午 · 高频必出（8 张，近 5 年每年出）

★高频进程三态1 分

考

画 6 条箭头的状态图，问"哪条转换不存在"。

懂

三态是"有没有 CPU 资格"和"是否正在跑"的组合：就绪=有资格但排队等 CPU；运行=正在 CPU 上跑；阻塞=连资格都没有（在等磁盘/网络等资源）。阻塞的进程不可能直接跳到运行——必须先等资源到位变回就绪，再排队被调度。

算

不存在的转换：阻塞→运行。存在的：就绪⇄运行（调度上去/时间片到下来）、运行→阻塞（主动等 I/O）。

坑

"运行→阻塞"可以直接发生（运行中主动等资源），别误判它不存在。

★高频范式判定1~2 分

考

给关系模式和函数依赖，判最高满足第几范式。

懂

范式是"消除冗余和异常"的等级：2NF 管"非主属性只依赖联合主键的一部分"（部分依赖）；3NF 管"非主属性通过其他非主属性间接依赖候选码"（传递依赖）。判定的前提是先求候选码、分清主属性（在候选码里的）和非主属性。

算

例 R(A,B,C,D)，A→B、B→C、A→D：①只有 A 从不做右边 → 候选码 A，A⁺=全部属性；②非主属性 B/C/D，候选码是单属性 → 无部分依赖 → 2NF ✓；③A→B→C 是传递依赖 → 不满足 3NF → 最高 2NF；分解 R1(A,B,D)+R2(B,C) 达 3NF。

坑

单属性候选码自动满足 2NF（没有"部分"可言）；"最高满足第几范式"=从 2NF 往上查，第一个不满足的停。

★高频信息安全1~2 分

考

给场景问"用什么技术/保证了什么性质"。

懂

四个工具各管一件事：摘要（MD5/SHA）管完整性（数据没被改过）；数字签名=完整+防抵赖（用只有自己才有的私钥签，人人可验但无法伪造）；对称加密管保密（快，但密钥怎么安全给对方是难题）；非对称加密管保密+密钥分发（公钥随便给，私钥自己留，但慢）。所以实际系统混合用：非对称传对称密钥，对称加密大数据。

算

"确保文件没被篡改"→摘要；"确保对方不能赖账"→数字签名；"既保密又防抵赖"→签名+加密。算法对号：AES/DES/RC4=对称，RSA/ECC=非对称；IDS 只报警、IPS 能阻断。

坑

签名不保密、加密不防抵赖——两个"保证"别混；摘要本身也不是加密。

★高频新技术1~3 分

考

给一句话描述选名词，或给名词问特征。

懂

云计算三层按"用户管多少"划分：IaaS 只租硬件（虚拟机/存储），操作系统以上自己管；PaaS 租"装好环境的平台"，只管写代码；SaaS 连软件都是现成的，打开就用。层级越高用户管得越少。大数据 4V 描述特征：大量/高速/多样/价值密度低。

算

"租服务器和存储，系统自己装"→IaaS；"只管写代码，环境平台管"→PaaS；"打开浏览器直接用"→SaaS。区块链=去中心化+不可篡改+智能合约；CI/CD=DevOps；就近处理=边缘计算。

坑

区块链的"去中心化"指没有中央管理机构，不是没有服务器。

★高频SQL 关键字1 分

考

给需求选子句，或给语句问功能。

懂

SELECT 的执行顺序：FROM→WHERE（筛原始行）→GROUP BY（分组）→HAVING（筛统计后的组）→SELECT（投影）→ORDER BY（排序）。WHERE 在分组前筛行，HAVING 在分组后筛组——所以聚合函数只能出现在 HAVING 里。

算

"每个部门平均工资>8000"→GROUP BY 部门 HAVING AVG(工资)>8000；"允许对方再把权限授给别人"→WITH GRANT OPTION；收回权限→REVOKE；虚表→视图。

坑

WHERE 里写 AVG() 直接错；视图不存数据，作用是安全和逻辑独立性。

★高频校验码 + 海明1 分

考

求海明码校验位数，或问哪种码能纠错。

懂

k 个校验位要能指出"错在哪"：需要区分 n 个数据位+k 个校验位各自出错、外加 1 种"没错"的情况，共 n+k+1 种状态，所以 2^k ≥ n+k+1。奇偶校验只能发现"奇数个位出错"（不能定位）；CRC 用模 2 除法生成校验串，检错能力强但不能定位（因此不能纠）。

算

n=8：k=4（2⁴=16 ≥ 8+4+1=13 ✓；k=3 时 8＜12 ✗）。

坑

"能纠 1 位错"的只有海明码；CRC 检错强≠能纠错。

★高频死锁1 分

考

四条件辨析、给措施问属于预防/避免/检测。

懂

死锁=互相抱着资源等对方。四个必要条件缺一个都不成立：互斥（资源一次一人用）、请求保持（抱着旧资源要新的）、不剥夺（不能抢别人的）、环路等待（形成等待圈）。对策分三层：预防=提前破坏某个条件（如一次性申请全部资源）；避免=运行时判断这次分配是否安全（银行家算法）；检测恢复=先放任发生再解除。

算

银行家算法→避免；"一次性申请所有资源"→预防（破坏请求保持）；"资源按序分配"→预防（破坏环路等待）。

坑

预防/避免/检测恢复三层考题爱混——银行家是"避免"不是"预防"。

★高频专业英语固定 5 分

考

150~200 词技术短文挖 5 空，四选一。

懂

5 空几乎全考"词性+固定搭配"，不考文章深度理解。名词前常有 the/of/for；动词前常有 to/can/must；形容词后跟名词。主题固定在软件工程领域（需求/测试/维护/面向对象），高频词就是那些术语的英文名。

算

三步：①判断空格需要什么词性 → ②排除词性不符的选项 → ③剩下的按搭配和句意选。高频词：requirement、specification、maintenance、integration、interface、object-oriented。

坑

别通读全文浪费时间；每个空只看前后一句就够。

★必试题一 数据流图15 分送分段

考

补数据流/补实体/补加工名，或问父子图是否平衡。

懂

数据流图的所有答案都藏在题干文字和图里：加工="动词+名词"的动作；实体=数据的源头或终点（人/组织/外部系统）；数据流=名词性的传输内容。黑洞=只进不出的加工（数据进去没产出）；奇迹=只出不进（凭空产出）。

算

三步：①逐个加工检查输入输出是否齐全（找黑洞/奇迹）→②对照题干把每句话标注到图上元素→③父子图逐条对账（0 层有的输入输出子图必须有）。命名规范=动词+名词（"生成报表"），不写笼统的"处理"。

坑

答案是从题干"找"出来的，写题干原词最稳；父子平衡漏一条扣一分。

★必试题二 数据库设计15 分送分段

考

补 E-R 图联系及类型、转关系模式并标主外键。

懂

联系类型判断=两边各问一次"一个对应几个"。转换规则的本质：1:n 时 n 端每个对象本来就只关联一个 1 端对象，把 1 端主键塞进 n 端当外键即可；m:n 时塞进谁都会出现"一格多个值"（违反 1NF），只能独立建表，主键用两端主键组合。

算

四步：①圈名词定实体 →②两边各问定联系类型 →③"成绩/数量/金额"这类挂联系上 →④转模式：1:n 并 n 端、m:n 独立建表、1:1 随便并（并入端加对方主键）。

坑

1:n 别独立建表（那是 m:n 的待遇）；m:n 表要写"两端主键都是外键"；新需求题先判断数据挂在谁身上。

★必试题三 UML15 分送分段

考

填类图关系箭头、补用例图，最后一问常考设计模式。

懂

六关系靠记号区分：泛化/实现都是三角箭头（实线=继承父类、虚线=实现接口），三角指向父/接口；依赖=虚线箭头（临时用一下）；关联=实线（长期持有）；聚合=空心菱形（整体-部分可分离，菱形画在整体端）；组合=实心菱形（同生共死）。用例图：include=必选复用（虚线指向被包含用例）；extend=可选扩展（方向相反）。

算

最后一问三句话模板："采用观察者模式"+"因为××状态变化时需要自动通知所有依赖它的对象"+"图中 Subject 对应××类、Observer 对应××类"。

坑

extend 箭头方向与 include 相反；菱形别画在"部分"那端。

★必试题六 Java（选答）15 分

考

给场景描述+类图+不完整框架代码，填 3~5 个空。

懂

下午 Java 题的骨架固定：单例=私有静态实例+私有构造+public static getInstance()；观察者=目标持观察者列表+notify 循环调 update；装饰器=实现组件接口并持有同类型成员变量（套娃包装）；策略=接口+多实现类+上下文调用。空里填的无非是"接口名/成员变量/方法调用"三类。

算

三步：①读场景第一句定模式 → ②看每个空在类图中的位置（接口名/成员/方法体）→ ③从骨架搬关键词，方法体里的调用照类图方法名抄。

坑

先抄类图再写代码；只主攻 Java，考场上直接选试题六放弃 C++。
