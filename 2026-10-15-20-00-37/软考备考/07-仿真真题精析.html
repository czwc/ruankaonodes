试题一 · 数据流图（15 分）必答

【题干】某医院开发"门诊预约挂号系统"，功能描述如下：
① 患者（注册用户）通过手机提交预约申请，系统根据科室排班表检查该科室当天剩余号源，若有号源则扣减号源，并向患者发送预约成功通知；若无号源则发送预约失败通知。
② 患者就诊当天到签到机刷卡签到，系统核对预约记录后，为患者生成就诊排队号。
③ 医生诊疗结束后录入诊疗结果，系统将其保存在诊疗记录中，并向患者发送取药提醒。
④ 系统管理员（排班员）负责录入各科室的排班信息，存入科室排班表。
系统将患者的预约信息登记在预约记录表中，将各科室排班与号源保存在科室排班表中，将每次诊疗的信息保存在诊疗记录表中。
【问题】（共 3 问）
(1) 根据题干说明，指出该系统数据流图中的外部实体与数据存储分别有哪些。（5 分）
(2) 0 层图中：加工 P2"签到处理"画了输入流"签到信息"，但没有任何输出流；同时 0 层图中出现了一条顶层图上不存在的数据流"欠费名单"。请指出图中存在的问题，并分别说明理由。（5 分）
(3) 写出数据流"预约成功通知"的起点和终点。（5 分）
问 (1) 评分点（每个 0.5~1 分）：
① 外部实体：患者、医生、排班员（3 个）。陷阱：手机/签到机是设备通道，不是外部实体——它们是患者与系统交互的媒介；若把"签到机"当实体写，通常扣分。
② 数据存储：预约记录表、科室排班表、诊疗记录表（3 个）——全部来自题干"登记在/保存在/存入"句式。

问 (2) 评分点（每个问题 2.5 分）：
① P2"签到处理"只有输入没有输出 → 黑洞错误（应有输出"就诊排队号"，题干②明确写了生成排队号）。答题句式："加工 P2 只有输入数据流而无输出数据流，存在黑洞错误；应补充数据流'就诊排队号'。"
② "欠费名单"在顶层图没有、0 层图有 → 违反父子平衡原则（父子平衡双向：子图有的流父图也必须有）。答题句式："数据流'欠费名单'出现在 0 层图但顶层图中没有，违反父子平衡原则。"

问 (3) 评分点：
起点：加工 P1（预约处理）；终点：外部实体"患者"。
定位方法：题干①"若有号源则扣减号源，并向患者发送预约成功通知"——生成它的加工是起点（P1），接收方"患者"是终点。
常见丢分：①把"手机/签到机"写成外部实体；②只答"黑洞"不写"应补什么流"（通常要补全才给满分）；③起点终点写成数据存储。

试题二 · 数据库设计（15 分）必答

【题干】某网店销售系统的部分需求如下：
① 每件商品（商品号、商品名、单价）由唯一的供应商（供应商号、名称、地址）供货；一个供应商可供应多种商品。
② 顾客（顾客号、姓名、电话）可购买多种商品，每种商品可被多名顾客购买；顾客购买商品时系统需记录购买数量与购买日期。
③ 每件商品属于一个类别（类别号、类别名），每个类别包含多件商品。
【问题】（共 4 问）
(1) 补充下列联系类型：供应商—商品（　）、顾客—商品（　）、类别—商品（　）。（4 分）
(2) "购买数量""购买日期"应放在哪里？（3 分）
(3) 将 E-R 模型转换为关系模式，写出每个关系模式的主键与外键。（5 分）
(4) 新增需求：顾客可对每件商品发表多条评论（评论内容、评论时间），请说明 E-R 图与关系模式应如何修改。（3 分）
问 (1) 评分点：供应商—商品：1:n（一件商品唯一供应商）；顾客—商品：m:n（双向多）；类别—商品：1:n。（每个 1.3 分左右，判错一个整体丢 4 分）

问 (2) 评分点：购买数量/日期属于"某位顾客买了某件商品"这件事本身 → 挂在 m:n 的"购买"联系上（既不属于顾客也不属于商品）。答"放购买联系"即得分；答放顾客表或商品表不给分。

问 (3) 评分点（每个模式 1~1.5 分）：
供应商(供应商号, 名称, 地址)
类别(类别号, 类别名)
商品(商品号, 商品名, 单价, 供应商号, 类别号)　← 两个 1:n 联系并入 n 端商品表，外键=供应商号、类别号
顾客(顾客号, 姓名, 电话)
购买(顾客号, 商品号, 购买数量, 购买日期)　← m:n 独立建表，主键=(顾客号,商品号)，二者都是外键

问 (4) 评分点：评论是"顾客—商品"之间新的独立联系且一名顾客可对同一商品多次评论（多条），不能与"购买"混用 → 新增联系"发表"（顾客—商品，1:n 或 m:n 视题干，多条评论按 1:n 处理：一个顾客多条评论、一条评论只属一个顾客）；新增关系模式：评论(评论号, 顾客号, 商品号, 评论内容, 评论时间)，主键=评论号，顾客号、商品号为外键。原有模式不变。
常见丢分：①把"购买"写成 1:n；②商品表漏写两个外键；③问(4)直接在"购买"表里加评论字段（评论与购买是两件事，真题爱考这个辨析）。

试题三 · UML 建模（15 分）必答

【题干】某在线考试系统的部分需求如下：
① 考生参加考试前，系统必须先完成"身份核验"；交卷时若超出考试时长，系统额外执行"强制收卷"并标记超时。
② 一场考试（考试编号、科目、时长）包含多道试题（题号、题型、分值）；一道试题可被多场考试复用；试题可以独立于任何考试预先录入题库。
③ 一场考试的生命周期：从"未开始"进入"进行中"，考生交卷（或强制收卷）后进入"已交卷"，阅卷完成后进入"已出分"。
【问题】（共 3 问）
(1) 画出用例图的参与者；说明"身份核验""强制收卷"分别与"参加考试/交卷"用例的关系，并写明箭头方向。（6 分）
(2) 指出"考试—试题"的关系类型（泛化/实现/组合/聚合/关联/依赖），并写出连线两端的多重性。（4 分）
(3) 按"事件[条件]/动作"格式，写出"进行中 → 已交卷"这条状态转移上应标注的内容。（5 分）
问 (1) 评分点：
参与者：考生（题干中与系统直接交互的角色；"在线考试系统"本身不是参与者）。
身份核验：每次考试必做 → «include»，箭头：参加考试 → 身份核验（指向被包含用例）。
强制收卷：仅超时才触发 → «extend»，箭头：强制收卷 → 交卷（扩展用例指向被扩展的基用例）。
方向写反是本题最常见的 4 分大坑——include 指向"小功能"，extend 指向"大用例"。

问 (2) 评分点：
试题可以独立于考试存在（预先录入题库）→ 不是组合，判 聚合（空心菱形画在"考试"整体端）。
多重性：考试端 1 —— 1..* 试题端（一场考试 1 到多道题；一道题可被 0..* 场考试复用，故严格写法：考试端 * 或 0..*，试题端 1..*——两种方向写对一种并说明含义即得分）。
依据句式："题干出现'可以独立存在'判聚合；'随之消失/不可独立'判组合。"

问 (3) 评分点：转移标注 = 交卷[未超时]/保存答卷 或 超时[超过考试时长]/强制收卷——写出"事件 + [条件] + /动作"三段中至少事件与条件两段（各 2 分左右），格式完整给满分。
常见丢分：①include/extend 箭头方向写反；②组合/聚合不看题干暗示乱选；③状态转移只写事件漏写 [条件]。

试题四 · 算法策略（15 分）必答

【题干】某算法求一维整数数组 a[0..n-1] 的最大子段和（连续若干个元素之和的最大值）。其 C 代码如下： 
int maxSum(int a[], int n) {
    int b = 0, sum = 0, i;      // b：以当前元素结尾的最大子段和
    for (i = 0; i < n; i++) {
        if (b > 0)
            b = (1)____;
        else
            b = (2)____;
        if (b > sum)
            sum = (3)____;
    }
    return sum;
}
【问题】（共 3 问）
(1) 填空 (1)~(3)。（6 分）
(2) 该算法采用的策略是什么？写出它的递推式（状态转移方程）。（5 分）
(3) 该算法的时间复杂度是多少？数组 a = {-2, 1, -3, 4, -1, 2, 1, -5} 时，返回值是多少？（4 分）
问 (1) 评分点（每空 2 分）：
(1) b + a[i]（前面的累加和为正就"带着走"，继续延伸子段）；
(2) a[i]（前面的累加和 ≤ 0 就"重新起头"，从当前元素开始新子段）；
(3) b（全局最大值随时被 b 刷新）。
填空技巧：注释里"以当前元素结尾"已经暗示了递推含义，先读懂注释再填。

问 (2) 评分点：策略：动态规划（2 分）。递推式（3 分）：b[j] = max( b[j-1] + a[j], a[j] )，答案 sum = max{ b[j] }。术语得分点：最优子结构 / 递推 / 填表（写出"以 j 结尾"的子问题定义更好）。

问 (3) 评分点：复杂度 O(n)（2 分，单层循环）；返回值 6（2 分，子段 [4, -1, 2, 1]）。
常见丢分：①(1)(2) 填反（判断条件是 b > 0，正才延续）；②递推式漏写 else 分支；③手算返回值算成 7（4-1+2+1=6，别把 -5 算进去）。

试题六 · Java 程序设计（15 分，与试题五二选一）建议选答

【题干】某电商平台按顾客等级计算订单折扣：普通顾客原价，VIP 顾客 8 折，SVIP 顾客 7 折。系统采用的设计模式类图描述为：抽象折扣接口 Discount 声明方法 calc(double money)；三个具体折扣类 NormalDiscount、VipDiscount、SvipDiscount 实现该接口；订单环境类 OrderContext 持有一个 Discount 类型的成员，checkout 时委托其计算价格。代码如下： 
interface Discount { double calc(double money); }

class NormalDiscount implements Discount {
    public double calc(double money) { return money; }
}
class VipDiscount implements Discount {
    public double calc(double money) { return money * 0.8; }
}
class SvipDiscount implements Discount {
    public double calc(double money) { return money * 0.7; }
}
class OrderContext {
    private (1)____ discount;
    public void setDiscount((2)____ d) { (3)____ = d; }
    public double checkout(double money) { return (4)____.calc(money); }
}
// 使用：ctx.setDiscount(new VipDiscount()); ctx.checkout(200);
【问题】（共 3 问）
(1) 填空 (1)~(4)。（8 分）
(2) 该代码体现的设计模式是什么？写出其意图。（4 分）
(3) 新增"满 300 减 50"规则时，系统需要修改哪些类？这体现了该模式的什么优点？（3 分）
问 (1) 评分点（每空 2 分）：
(1) Discount（环境类成员类型 = 抽象策略接口）；
(2) Discount（set 方法参数类型 = 同一抽象接口）；
(3) this.discount（区分成员变量与参数 d）；
(4) discount（用成员变量名调用，运行时多态分派到具体折扣类）。
四空全部是"抽象类型 + this + 变量名"三板斧，照类图抄即可。

问 (2) 评分点：模式：策略（Strategy）（2 分）。意图：定义一系列算法（折扣规则），把它们一个个封装起来，并使它们可以互相替换，算法的变化不影响使用算法的客户（2 分，"封装 + 可替换"两个关键词）。

问 (3) 评分点：只需新增一个具体策略类（如 FullReductionDiscount 实现 Discount），OrderContext 与既有折扣类无需修改（2 分）。体现的优点：对扩展开放、对修改关闭（开闭原则），新增算法不改动已有代码（1 分）。
常见丢分：①(3) 填 discount 漏了 this.；②意图只写"换算法"漏"封装/不影响客户"关键词；③问(3)答"修改 OrderContext 加 if 判断"——那正是该模式要消除的写法。
