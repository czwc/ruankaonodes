GoF 23 个设计模式全解

三大类 23 式逐个过：意图必背 → 题干信号词 → 代码骨架 → 填空点。上午题认得出、下午题填得对

① 总览与分类记忆 ② 创建型 5 式 ③ 结构型 7 式 ④ 行为型 11 式 ⑤ 易混对比（陷阱表） ⑥ 训练题 ⑦ 考场清单

① 总览：23 式一张地图 先背分类

类别解决什么问题模式（23 个）
创建型 5对象怎么创建（把 new 藏起来）单例、工厂方法、抽象工厂、建造者、原型
结构型 7类和对象怎么组合成大结构适配器、桥接、组合、装饰器、外观、享元、代理
行为型 11对象之间怎么交互、分配职责策略、模板方法、观察者、迭代器、职责链、命令、备忘录、状态、访问者、中介者、解释器
分类速记：名字带"工厂/单例/建造/原型"→创建型；带"包装味"（装饰/适配/代理/外观/桥接/组合/享元）→结构型；其余全是行为型（数量最多，考试出题也最多）。软考高频 Top6：策略、观察者、装饰器、单例、工厂方法、状态——这 6 个必须能默写骨架，其余认得意图即可。

② 创建型 5 式：把"new"管起来

1. 单例 Singleton ★高频

意图：保证一个类仅有一个实例，并提供一个全局访问点。
题干信号："全局唯一""只允许创建一个""连接池/配置管理器/日志对象/打印机任务管理"。
class Config {
    private static Config instance;          // 唯一实例
    private Config() {}                      // 私有构造：禁止 new
    public static Config getInstance() {
        if (instance == null) instance = new Config();
        return instance;
    }
}
填空点：private 构造、private static 实例、public static getInstance() 三件套轮着挖。

2. 工厂方法 Factory Method ★高频

意图：定义创建对象的接口，让子类决定实例化哪个类。把实例化延迟到子类。
题干信号："具体创建哪个对象由子类决定""新增产品只需新增工厂子类"。
abstract class LoggerFactory {
    public abstract Logger createLogger();  // 工厂方法：返回抽象产品
}
class FileLoggerFactory extends LoggerFactory {
    public Logger createLogger() { return new FileLogger(); }  // 子类决定
}
填空点：工厂方法返回抽象产品类型；具体工厂里 new 具体产品。

3. 抽象工厂 Abstract Factory

意图：提供一个创建一系列相关产品（产品族）的接口，无需指定具体类。
题干信号："一族/一系列相关产品""多套风格整体切换"（如 Windows 风格按钮+文本框 vs Mac 风格整套）。
interface GUIFactory {
    Button createButton();     // 不止一个创建方法 = 产品族
    TextBox createTextBox();
}
class MacFactory implements GUIFactory {
    public Button createButton() { return new MacButton(); }
    public TextBox createTextBox() { return new MacTextBox(); }
}
填空点：抽象工厂接口有多个创建方法（和工厂方法的本质区别）；具体工厂实现全部方法。

4. 建造者 Builder

意图：把复杂对象的构建过程分步进行，同样的构建过程可以创建不同的表示。
题干信号："分步骤/分部分构建""组装""同样的过程创建不同表示"（如拼装电脑：CPU→内存→硬盘）。
interface Builder { void buildCPU(); void buildMem(); Computer getResult(); }
class HighEndBuilder implements Builder { /* 逐步构建高端机 */ }
class Director {                            // 指挥者：固定构建顺序
    public Computer construct(Builder b) {
        b.buildCPU(); b.buildMem();          // 分步调用
        return b.getResult();
    }
}
填空点：Director 逐步调用 Builder 的 buildXxx()；Builder 提供 getResult() 返回产品。

5. 原型 Prototype

意图：用原型实例指定要创建对象的种类，通过拷贝（clone）这个原型来创建新对象。
题干信号："克隆/复制已有对象来创建""对象初始化成本高，直接复制"。
abstract class Shape implements Cloneable {
    public Shape clone() { ... }             // 核心方法：克隆自己
}
// 使用：Shape s2 = cachedShape.clone();  不走 new
填空点：clone() 方法；与工厂的区别——原型是"复制自己"，工厂是"新建"。

③ 结构型 7 式：怎么"包装"和"组装"

6. 适配器 Adapter

意图：把一个类的接口转换成客户期望的另一个接口，使接口不兼容的类可以一起工作。
题干信号："接口不兼容""复用已有类但接口不匹配""转接头"。
class Adapter extends Target {              // 实现目标接口
    private Adaptee adaptee;                  // 持有被适配的旧类
    public void request() { adaptee.specificRequest(); }  // 转发+翻译
}
填空点：适配类继承目标接口 + 持有被适配者引用，方法里做"翻译转发"。

7. 桥接 Bridge

意图：把抽象部分与实现部分分离，使两者可以独立变化。
题干信号："两个维度独立变化""避免类爆炸"（形状×颜色、遥控器×电视品牌）。
class RemoteControl {                        // 抽象维度
    protected TV tv;                          // ★持有"实现"维度接口的引用
    public void on() { tv.turnOn(); }
}
interface TV { void turnOn(); }              // 实现维度：SonyTV / XiaomiTV
填空点：抽象类持有实现接口的引用（聚合关系）。与策略结构几乎一样，靠题干"两个维度独立变化"区分。

8. 组合 Composite

意图：把对象组合成树形"部分-整体"层次，使客户对单个对象和组合对象的使用具有一致性。
题干信号："树形结构""文件与文件夹""容器与叶子同等对待"。
abstract class Component {                   // 叶子和容器的共同抽象
    public abstract void display();
}
class Folder extends Component {             // 容器：持有 Component 列表
    private List<Component> children = new ArrayList<>();
    public void add(Component c) { children.add(c); }
    public void display() { for (Component c : children) c.display(); }
}
填空点：容器类持有 List<Component>；display 递归遍历调用。

9. 装饰器 Decorator ★高频

意图：动态地给对象添加额外职责，比继承更灵活。
题干信号："动态添加职责/功能""不改变原类的前提下增强"。
abstract class CoffeeDecorator implements Coffee {
    protected Coffee coffee;                  // 持有同类型引用
    public double cost() { return coffee.cost(); }   // 委托
}
class Milk extends CoffeeDecorator {
    public double cost() { return coffee.cost() + 2.0; }  // 委托+加料
}
填空点：三标志——继承同一抽象 + 持有同类型引用 + 委托再加料。详见 05 篇精讲。

10. 外观 Facade

意图：为子系统中的一组接口提供一个一致的高层界面（统一入口），降低耦合。
题干信号："统一入口""简化使用""封装一层"（一键启动：自动调 CPU→内存→硬盘检查）。
class ComputerFacade {
    public void start() {
        new CPU().start();        // 一个方法里依次
        new Memory().check();     // 调用多个子系统方法
        new Disk().read();
    }
}
填空点：外观类的方法里依次调用多个子系统的方法。没有"持有+翻译"，就是打包简化。

11. 享元 Flyweight

意图：用共享技术支持大量细粒度对象的复用，减少内存。
题干信号："系统中存在大量相似/重复对象""共享池"（棋子、文字字符、图标缓存）。
class ChessPieceFactory {
    private static Map<String, ChessPiece> pool = new HashMap<>();
    public static ChessPiece get(String color) {
        pool.putIfAbsent(color, new ChessPiece(color));   // 有就复用
        return pool.get(color);
    }
}
填空点：工厂里有 Map/池 + "存在即复用，不存在才创建"逻辑。

12. 代理 Proxy

意图：为其他对象提供一个代理以控制对它的访问。
题干信号："访问控制/权限校验""远程调用""延迟加载""图片加载前先显示占位"。
class ImageProxy implements Image {          // 与真实类同接口
    private RealImage real;
    public void display() {
        if (real == null) real = new RealImage();  // 延迟加载/权限检查
        real.display();
    }
}
填空点：代理与真实类实现同一接口，代理内部 new 真实类。与装饰器结构相同，区别在意图：代理管"访问控制"，装饰器管"加职责"。

④ 行为型 11 式：对象间怎么交互（出题最多）

13. 策略 Strategy ★最高频

意图：定义一系列算法，把它们一个个封装起来，并使它们可以互相替换。
题干信号："算法可动态切换""不同促销/计费/排序方式"。
interface Discount { double calc(double money); }
class OrderContext {
    private Discount discount;                // 持抽象策略
    public void setDiscount(Discount d) { this.discount = d; }
    public double checkout(double m) { return discount.calc(m); }
}
填空点：三板斧——成员类型=接口、参数=接口、调用=成员变量名。详见 05 篇。

14. 模板方法 Template Method ★高频

意图：父类定义算法的骨架，把某些步骤延迟到子类实现。
题干信号："固定步骤/流程顺序不变，个别步骤子类不同"（泡饮料：烧水→冲泡→倒杯，冲泡各不同）。
abstract class DrinkMaker {
    public final void make() {                // 骨架固定顺序
        boil(); brew(); pour();
    }
    private void boil() {} private void pour() {}
    protected abstract void brew();           // 变化步骤留给子类
}
填空点：父类骨架方法（常 final）+ abstract 步骤方法。

15. 观察者 Observer ★高频（2023 真题三问题3）

意图：定义对象间一对多依赖，主题状态变化时自动通知所有依赖者。
题干信号："注册/订阅/关注""状态变化时及时通知"。
interface Observer { void update(int count); }
class Resource {
    private List<Observer> obs = new ArrayList<>();
    public void attach(Observer o) { obs.add(o); }       // 注册
    public void changed() { for (Observer o : obs) o.update(n); }  // 通知
}
填空点：List<Observer>、attach 遍历 update。作答模板见 03 篇考场清单第 6 步。

16. 迭代器 Iterator

意图：提供一种方法顺序访问聚合对象中的元素，而不暴露内部表示。
题干信号："遍历集合不暴露内部结构""hasNext()/next()"。
interface Iterator_ { boolean hasNext(); Object next(); }
class BookList {
    public Iterator_ createIterator() { return new ListIterator_(this); }
}
填空点：hasNext / next 两个方法；集合类提供 createIterator()。

17. 职责链 Chain of Responsibility

意图：多个处理者连成一条链，请求沿链传递，每个处理者决定处理或传给下一个。
题干信号："逐级审批""请求沿链传递直到被处理"（请假：组长→经理→总监）。
abstract class Handler {
    protected Handler next;                    // 持有下一节点
    public void setNext(Handler n) { next = n; }
    public abstract void handle(Request r);     // 处理不了就 next.handle(r)
}
填空点：持有同类型 next 引用 + "能处理则处理，否则 next.handle()"。

18. 命令 Command

意图：把请求封装成对象，从而支持请求的参数化、排队、日志和撤销/重做。
题干信号："撤销/重做""请求排队/记录日志""按钮与具体动作解耦"。
interface Command { void execute(); void undo(); }
class LightOnCommand implements Command {
    private Light light;                        // 持有接收者
    public void execute() { light.on(); }
    public void undo() { light.off(); }
}
// 遥控器：按按钮 → command.execute()；撤销栈 → undo()
填空点：execute/undo 方法；命令对象持有接收者（Receiver）。

19. 备忘录 Memento

意图：在不破坏封装的前提下，捕获对象内部状态并保存，以便以后恢复。
题干信号："存档/快照""撤销恢复到之前状态"（游戏存档、编辑器 Ctrl+Z 的状态备份）。
class Editor {
    private String text;
    public Memento save() { return new Memento(text); }   // 存档
    public void restore(Memento m) { text = m.getText(); } // 恢复
}
填空点：save()/restore() 两个方法；备忘录对象只存状态。与命令的区别：备忘录存"状态"，命令存"操作"。

20. 状态 State ★高频

意图：对象的行为随其内部状态改变而改变，像"切换了类"一样。
题干信号："不同状态有不同行为""状态很多、switch 臃肿"（电梯、订单流转、TCP 连接）。
interface OrderState { void handle(Order o); }
class Order {
    private OrderState state;                  // 持当前状态对象
    public void request() { state.handle(this); }
    public void setState(OrderState s) { state = s; }   // 状态子类里切换
}
填空点：环境类持状态引用；状态子类里调用 o.setState(...) 切换状态。与策略结构相同，区别：状态由内部自动流转，策略由客户主动设置。

21. 访问者 Visitor

意图：封装作用于某结构中各元素的操作，可在不改变元素类的前提下定义新操作。
题干信号："数据结构稳定、对元素的操作经常变化""对结构施加新操作"。
interface Visitor { void visit(FileA f); void visit(FileB f); }
abstract class Element { public abstract void accept(Visitor v); }
class FileA extends Element {
    public void accept(Visitor v) { v.visit(this); }   // 双分派
}
填空点：accept(Visitor) 里回调 v.visit(this)——"双分派"是识别标志。

22. 中介者 Mediator

意图：用一个中介对象封装一系列对象的交互，使各对象不需显式相互引用，松耦合且可独立变化。
题干信号："多对象之间交互复杂、网状引用""集中调度"（机场塔台、聊天室服务器、MVC 的控制器）。
abstract class Colleague {
    protected Mediator mediator;               // 都只认识中介
}
class ChatMediator implements Mediator {
    public void send(String msg, User from) {   // 由中介转发
        for (User u : users) if (u != from) u.receive(msg);
    }
}
填空点：同事类持中介引用；交互逻辑集中在 mediator 里转发。与观察者区别：中介者是"多对多经中转"，观察者是"一对多广播"。

23. 解释器 Interpreter

意图：给定一个语言，定义它的文法表示，并定义一个解释器来解释语言中的句子。
题干信号："自定义规则语言""表达式解析""文法"（正则引擎、SQL 解析、计算器表达式树）。
interface Expr { int interpret(); }
class Add implements Expr {                    // 文法规则 = 类
    private Expr left, right;
    public int interpret() { return left.interpret() + right.interpret(); }
}
填空点：每条文法规则一个类 + interpret() 递归求值。考试认得即可，很少考填空。

⑤ 易混对比：选择题陷阱全在这 必背

易混组本质区别（一句话）题干怎么区分
代理 vs 装饰器结构相同，意图不同：代理控制访问，装饰器加职责"权限/远程/延迟"→代理；"增强功能"→装饰器
外观 vs 适配器外观简化打包多个子系统；适配器转换一个不兼容接口"统一入口"→外观；"接口不匹配"→适配器
工厂方法 vs 抽象工厂工厂方法一个产品；抽象工厂一族产品看接口里有几个 createXxx 方法
状态 vs 策略结构相同：状态内部自动流转；策略由客户主动换"状态改变行为跟着变"→状态；"算法可切换"→策略
命令 vs 备忘录命令封装操作（能重放）；备忘录保存状态快照"撤销重做操作"→命令；"恢复到之前状态"→备忘录
桥接 vs 装饰器桥接分离两个变化维度；装饰器层层叠加职责"两维度独立变化"→桥接；"动态加职责"→装饰器
观察者 vs 中介者观察者一对多广播；中介者多对多经中转"主题通知订阅者"→观察者；"多对象互不认识靠调度"→中介者
组合 vs 装饰器组合是树形聚合（部分-整体）；装饰器是链式包装"树/文件夹"→组合；"套娃加功能"→装饰器
终极判断流程：先问"管创建还是管行为还是管结构"→ 再看题干关键词对号 → 结构型优先排"访问控制(代理)/接口转换(适配)/树形(组合)" → 行为型优先排"通知(观察者)/切换(策略)/流转(状态)"。宁可对照排除，不要凭感觉。

⑦ 考场执行清单

背诵分级：①能默写骨架：策略、装饰器、观察者、单例、工厂方法、状态（6 个）；②能说清意图+信号词：模板方法、代理、适配器、外观、桥接、命令、备忘录、职责链（8 个）；③认得即可：抽象工厂、建造者、原型、组合、享元、迭代器、访问者、中介者、解释器（9 个）。
