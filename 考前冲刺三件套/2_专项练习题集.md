## 第 2 题(PV 操作含义)
对信号量 S 执行 P 操作后,S 的值变为 -3,说明有几个进程在等待?

- C. 3
- D. 4

<details>

**答案:C**

**口诀**:P 后负几等几个。

## 第 3 题(生产者-消费者,经典)
生产者-消费者问题中,需要几个信号量?初值分别是什么?
- A. 1 个,初值 1
- B. 2 个,初值都为 1
- C. 3 个:互斥量 1、空槽量 N、满量 0
- D. 2 个:空槽量 N、满量 0

<details>
<summary>👉 点击看解析</summary>

**答案:C**

**解析**:
- 互斥信号量(保护缓冲区):初值 1。
- 空槽数(空闲位置):初值 N。
- 满数(已有数据):初值 0。

**关键易错**:不能只用 2 个,必须有互斥量!

**P 操作顺序**(生产者):P(空槽) → P(互斥) → 放数据 → V(互斥) → V(满)
**注意**:P(互斥) 不能在 P(空槽) 前面,否则会死锁。
</details>

## 第 5 题(死锁计算)
系统有 3 个进程,每个进程最多需要 2 个资源,系统共有 6 个同类资源,会死锁吗?

<details>
<summary>👉 点击看解析</summary>

**答案:不会死锁**

**公式**:不死锁条件 M ≥ n × (R − 1) + 1

**代入**:M=6,n=3,R=2 → 6 ≥ 3×(2−1)+1 = 4 ✅

最坏情况:每个进程都拿了 R−1=1 个(共 3 个),还剩 3 个,任意再给 1 个进程就能满足。

**秒杀公式**:临界资源数 = n×(R−1)+1。
</details>

## 第 3 题(单例模式代码)
以下单例模式代码有什么问题?
```java
public class Singleton {
    private static Singleton instance;
    private Singleton() {}
    public static Singleton getInstance() {
        if (instance == null) {
            instance = new Singleton();
        }
        return instance;
    }
}
```

<details>
<summary>👉 点击看解析</summary>

**答案:线程不安全**

**问题**:多线程环境下,两个线程同时判断 instance == null 为 true,会创建两个实例。

**改进**(双重检查锁):
```java
public static synchronized Singleton getInstance() {
    if (instance == null) {
        synchronized (Singleton.class) {
            if (instance == null) {
                instance = new Singleton();
            }
        }
    }
    return instance;
}
```
</details>

### 第 9 题(并发问题)
"事务 T1 读到的数据是事务 T2 还没提交的,T2 后来回滚了"这种现象叫?

- B. 脏读

### 第 10 题(封锁协议)
下列哪种封锁协议能防止"不可重复读"?

- B. 二级封锁协议
- C. 三级封锁协议
- D. 两段锁协议

<details>
<summary>👉 点击看解析</summary>

**答案:C**

**解析**:
| 协议 | 加锁方式 | 防什么 |
|---|---|---|
| 一级 | 写前加 X 锁,事务结束释放 | 丢失修改 |

## 子模块 6:数据结构进阶(3 题)

### 第 16 题(B+ 树)
数据库索引多用 B+ 树而非 B 树,主要原因是?
- A. B+ 树比 B 树矮
- B. B+ 树的非叶子不存数据,查询更稳定,且叶子有链表支持范围查询
- C. B+ 树能存更多关键字

<details>
<summary>👉 点击看解析</summary>

**答案:B**

KMP 算法相比朴素字符串匹配,主要优势是?

### 第 19 题(静态/动态绑定)
C++ 中,以下哪种情况会触发"动态绑定"?
- A. 函数重载(overload)
- B. 模板函数
- C. 声明为 virtual 的成员函数,通过父类指针调子类重写的方法

<details>
<summary>👉 点击看解析</summary>

**答案:C**

**解析**:
| 绑定类型 | 时机 | 对应 |
|---|---|---|
| 静态绑定 | 编译期 | 重载、模板、非虚函数 |
| **动态绑定** | 运行期 | **虚函数(virtual)+ 指针/引用调用** |

### 第 20 题(存储类别)
C 语言中,函数内定义的 `static` 变量,以下说法正确的是?
- A. 存储在栈区,函数返回就销毁
- B. 存储在静态区,函数返回后仍保留,下次调用保留上次值
- C. 每次调用都重新初始化
- D. 其他函数也能直接访问

<details>
<summary>👉 点击看解析</summary>

**答案:B**

**解析**:
- `static` 局部变量:**存储在静态区,生存期 = 整个程序运行期**。

**口诀**:**static 最长寿**(活到程序结束),**auto 最短命**(函数返回就没);static 只初始化一次。

</details>

# 模块九:学习心法与拓展(小白进阶必读)

> 📌 **说明**:这部分不是考点,是教你怎么"学得会、记得住、考得过"。考试不是终点,但先把证拿下再说。

## 一、学软考到底在学什么

软考软件设计师考的不是"你会写多少代码",而是**"你懂不懂软件开发的整套体系"**。它像一个"软件行业地图":

- **上午题(综合知识)**:考你"见没见过"——75 道选择,覆盖计算机从硬件到法律的全景。
- **下午题(案例分析)**:考你"会不会用"——DFD、数据库、UML、算法、设计模式,5 道大题。

**关键认知**:
> 上午题拼**广度**,下午题拼**深度**。上午别死磕一个点,下午别只背不练。

---

## 二、小白常见的 5 个学习陷阱

### 陷阱 1:把软考当考研学
- ❌ 钻牛角尖,一个算法证明看 3 天。
- ✅ 软考是**通过型**(45 分万岁),不是选拔型。会做基础题就行,难题该放弃就放弃。

### 陷阱 2:只看视频不动手
- ❌ 视频看了 100 小时,觉得自己"都懂了"。
- ✅ 视频是"输入",做题才是"输出"。**看 1 小时视频,至少做 1 小时题**。看懂和会做差着十万八千里。

### 陷阱 3:贪多求全,资料囤一堆
- ❌ 下载 10 份笔记、5 本教材,每个都看一点。
- ✅ **一份核心资料反复看 + 5 套真题精刷**,比 10 份资料各看一遍强。这份攻略 + 真题就够过线。

### 陷阱 4:下午题靠背
- ❌ 背了 23 种设计模式的名字,以为下午能填空。
- ✅ 下午题考"应用"——给你场景代码,要你填空。**必须自己手写代码骨架**,光背名字没用。

### 陷阱 5:不掐时间做真题
- ❌ 一套真题做一天,慢慢查书。
- ✅ **严格掐时间**:上午 150 分钟、下午 150 分钟。考场上最大的敌人是时间,不是难度。

---

## 三、记忆的科学方法(背得快、记得牢)

### 方法 1:口诀记忆法(本攻略已大量使用)

**原理**:人脑记得住"有节奏、有压缩"的东西。口诀把一串信息压成几个字,回忆时再展开。

**例子**:
- 七层模型"物数网传会表应"→ 7 个字记 7 层。
- 死锁四条件"互请不环"→ 4 个字记 4 个条件。
- 设计模式分类"单工抽建原 / 适桥组装外享代 / 责命解迭中备观状策模访"。

**怎么自己造口诀**:
1. 提取每条信息的首字或关键字。
2. 编成顺口或谐音。
3. 越离谱越好记(比如"插冒归稳定"——想象插头冒烟了还得稳着用)。

### 方法 2:对比记忆法

**原理**:容易混的概念,放一起对比,差异点反而最深刻。

**例子**:
| 易混对 | 区别 |
|---|---|
| 重载 vs 重写 | 重载静态(编译期),重写动态(运行期) |
| 聚合 vs 组合 | 聚合可分离,组合共生死 |
| include vs extend | include 必做,extend 选做 |
| S 锁 vs X 锁 | S 读共享,X 写独占 |
| AVL vs 红黑树 | AVL 严格平衡,红黑近似平衡 |

**怎么做**:学新概念时,主动问"这和之前学的 XX 有啥区别?"。

### 方法 3:费曼记忆法(讲给别人听)

**原理**:能给别人讲清楚,才是真懂。

**操作**:
1. 学完一个考点。
2. 合上书,假装面前坐着一个完全不懂的朋友。
3. 用大白话讲一遍(比如"PV 操作就像抢厕所,先拿号才能进")。
4. 讲不下去的地方,就是你没懂的,回去重看。

### 方法 4:间隔重复(Spaced Repetition)

**原理**:艾宾浩斯遗忘曲线——刚学的 24 小时内忘 70%,但复习能大幅延缓遗忘。

**复习节奏**:
- 学完当天晚上:过一遍口诀。
- 第 2 天:盖住答案,重做错题。
- 第 7 天:整套真题复盘。
- 考前 3 天:只看口诀和公式表。

**工具建议**:可以用 Anki(间隔重复卡片 App),把易错点做成卡片。

### 方法 5:错题本(最重要)

**原理**:做对的题说明你会了,做错的题才是你的"提分金矿"。

**怎么做**:
1. 错题不是抄一遍,而是写下**"我当时为什么选错"**。
2. 再写**"正确思路是什么"**。
3. 标注**对应考点**(回攻略哪一节)。
4. 考前只翻错题本。

---

## 四、考场实战策略(把会的都拿住)

### 上午选择题(150 分钟,75 题)

**时间分配**:平均每题 2 分钟,但难度不均。

| 题型 | 建议时间 | 策略 |
|---|---|---|
| 简单记忆题(占 60%) | 每题 30 秒 | 快速选,不确定的标个"?" |
| 计算题(占 15%) | 每题 3-5 分钟 | 流水线、Cache、子网、可靠度——公式记牢直接套 |
| 代码/算法题(占 10%) | 每题 3 分钟 | 看选项差异,排除明显错的 |
| 英语阅读(占 5%) | 每题 1 分钟 | 先通读,按词性和上下文选 |
| 不会的(占 10%) | 30 秒 | 别纠结,蒙一个,留时间检查 |

**黄金法则**:
- **先扫一遍全部题目**,把一眼会的先做掉(建立信心 + 占住分数)。
- **标记不确定的题**,做完再回来想。
- **最后 10 分钟检查**,只改明确发现错的,没把握的别乱改(第一直觉往往对)。

### 下午大题(150 分钟,5 题)

**必答第 1 题:DFD(数据流图)**
- 这是最该拿满分的题。
- 套路:① 找外部实体 → ② 找加工 → ③ 找数据存储 → ④ 检查父子图平衡 → ⑤ 检查黑洞/奇迹。
- **数据流命名**:名词别用动词,加工命名:动词别用名词。

**选答题(2-5 题选 4 题):数据库 / UML / 算法 / 设计模式 + 面向对象**

| 题型 | 难度 | 建议 |
|---|---|---|
| 数据库(E-R + SQL) | ⭐⭐ | 优先做,套路固定(1:1/1:n/m:n 转关系) |
| UML(类图/用例图) | ⭐⭐ | 优先做,名词填属性、动词填方法 |
| 算法(C/C++ 填空) | ⭐⭐⭐⭐ | 最难,放最后;找上下文变量 + 死记模板 |
| 设计模式 + 面向对象(C++/Java) | ⭐⭐⭐ | 看接口方法名照抄;先填确定的,再猜难的 |

**选题策略**:
- **数据库 + UML 必选**(套路固定,稳)。
- **设计模式**:会就选,不会别硬刚。
- **算法**:实在没把握才选,而且只填能确定的空,剩下的按"上下文变量名"猜。

**时间分配**:每题 25-30 分钟,留 20 分钟检查填空。

## 五、考试之外,你还能学到什么(拓展认知)

软考不只是考证,它的知识体系本身就是一张"软件工程师必备地图"。学完之后,你应该:

### 1. 看懂"为什么这么设计"
- **设计模式**不是死记 23 种,而是理解"封装变化、针对接口编程、组合优于继承"。工作中写代码时,你会发现处处是模式(比如 Spring 的 AOP 用了动态代理、监听器用了观察者)。
- **SOLID 原则**:单一职责、开闭原则——这些是写出"好维护代码"的底子。

### 2. 看懂"系统怎么跑起来的"
- **从 CPU 到网络**:一条指令怎么执行 → 程序怎么编译 → 数据怎么存 → 网络怎么传——软考串起了整条链路。
- **操作系统**:进程、内存、文件——你写 Java/C# 调的 API,底层都是这些。理解了 OS,调试多线程、内存泄漏会更顺手。

### 3. 看懂"工程怎么管的"
- **软件工程**:需求 → 设计 → 编码 → 测试 → 维护。工作中你就是这条链上的一环,知道全流程才不会"只见树木不见森林"。
- **项目管理**:进度、成本、质量三角。哪怕你不当项目经理,懂这个能让你跟 PM 沟通更顺。

### 4. 看懂"数据怎么组织的"
- **数据结构 + 算法**:这是编程的内功。排序、查找、树、图——面试要考,工作要用(比如选 List 还是 Set、用 HashMap 还是 TreeMap)。
- **数据库**:范式、索引、事务——做后端开发天天打交道。懂事务隔离级别,能避免线上数据不一致的坑。

### 5. 看懂"安全怎么防的"
- **加密、签名、证书**:HTTPS、登录认证、支付加密,底层都是这套。理解了就不会犯"密码明文存数据库"这种低级错误。
- **攻击手段**:SQL 注入、XSS、重放——知道怎么打,才知道怎么防。

## 六、考完之后怎么继续提升

软考是"入门地图",不是"终点"。考完之后建议:

| 方向 | 做什么 |
|---|---|
| **动手能力** | 自己写一个完整项目:前端 + 后端 + 数据库,把设计模式用进去 |
| **深入一门语言** | Java:读《Effective Java》;C++:读《Effective C++》;Python:读源码 |
| **系统设计** | 读《大型网站技术架构》《设计数据密集型应用》 |
| **开源参与** | 去 GitHub 找感兴趣的项目,先读代码再提 PR |
| **软考进阶** | 高级有"系统架构设计师""信息系统项目管理师"——如果你想往架构/管理走 |

**记住一句话**:**软考是起点,不是终点。证书帮你过简历关,但真正让你走得远的,是把知识用起来的能力。**
